# `pyproject.toml` pins every DIRECT dependency with `==`; this file pins the TRANSITIVE ones
# too, because a direct pin alone let the image (PyPI) and CI (the PyTorch CPU index) resolve
# torch's own dependencies differently - filelock, fsspec, networkx, numpy (recorded in
# `0xcc/reviews/python_313_2026-10-21.md`). Both install with `-c constraints.txt`:
#   backend/Dockerfile:   pip install -c constraints.txt "torch==${TORCH_VERSION}" ".[bnb]"
#   backend-tests.yml:    pip install --no-deps torch==<pin> --index-url .../whl/cpu
#                         pip install -c constraints.txt -e ".[dev]"
# A constraint only CONSTRAINS: lines for packages an install does not need (the nvidia-* CUDA
# runtime in CI, the dev tools in the image) install nothing.
#
# `backend/tests/unit/test_dependencies_are_locked.py` fails when a direct dependency is
# unpinned, when this file disagrees with `pyproject.toml`, when an install path skips this
# file, or when the running environment holds a distribution this file does not pin (or pins
# differently) - so the image and CI cannot install different versions silently.
